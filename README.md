# x360-xuacs

The Xbox 360 account service (Live service 5 and its siblings served from one HTTP backend): `/xuacs/*.ashx` (sign-in, profile
recovery), the Windows Live ID login (`nexus.passport.com`, `login.live.com`, TLS), `/xsig` certificate validation,
`/xedl` CountryInfo, `/xpnfront/xpresence.srf` (presence alive), `/xbos/GetRevocationList.ashx` and the `/xstats/*` replies.
Also the internal user-key API the KDC uses for the user AS exchange.

Part of OpenPak's Xbox 360 stack: one repository and one image per service ([`x360-kdc`](../x360-kdc),
[`x360-gateway`](../x360-gateway), [`x360-xuacs`](../x360-xuacs), [`x360-liveinfo`](../x360-liveinfo),
[`x360-notice`](../x360-notice), [`x360-xexds`](../x360-xexds)) around the shared Go library
[`x360-common`](../x360-common) (`replace` + committed `vendor/`; after changing x360-common run
`go mod vendor` here and commit).


## Configuration

Environment `X360_XUACS_*` (see `deploy/primary/openpak-x360-xuacs.container` and `x360-common/config`): `ADDR`, `STATE`, `RSA_KEY`, `TLS_ADDR`, `INTERNAL_ADDR`, `INTERNAL_KEY`, `ACCOUNT_CORE_URL/TOKEN`, `DEBUG`.

## Build and test

`TMPDIR=<scratch> X360_KDC_TESTKEYS=<dir with the dev keys> go test -mod=vendor ./...`

Tag `vX.Y.Z` and CI publishes `ghcr.io/openpak/x360-xuacs:latest` (amd64 + arm64); hosts auto-update `:latest`.
`deploy/` holds the live quadlet and helpers. History before 2026-10-18 is the x360-kdc monorepo's, filtered to

## Native Friends snapshot

Presence-alive replies project accepted friends and the caller's own blocks
from account core. The core remains authoritative; xuacs applies its discovery
enforcement before exposing a friend. Canonical Xbox links and account handles
supply XUIDs and gamertags, including friends who use another OpenPak platform.
Content versions change when a list changes; an empty core graph clears a
previously cached list. Core failures return an error, never a fake empty graph.

The request XUID must be in the authenticated gateway tunnel's user projection.
`X-X360-Users` is an internal gateway header, stripped and regenerated by the
gateway; preserve that trust boundary when configuring routes.

This implements the initial accepted-friend/block snapshot. Friend-request
mutations, live friend-presence push updates, activity feed and Avatar Store
remain separate work. A server-side snapshot does not restore the dashboard's
missing online Social content package, nor establish physical-console parity.

Native service-5 opcode `0x63C` (`XeUserGetAgeGroup.ashx`) derives Child/Teen/Adult
from the active account's core birthday (under 13 / under 18 / 18 and older, UTC).
An uncollected birthday retains Child policy; malformed/future dates and core
failures return service unavailable. The requested XUID must be on the tunnel
ticket. Native presence logoff (`0x400`, XRL `0xF`) acknowledges the ticket-bound
XUID with an empty HTTP 200. If the active ticket has already dropped the user,
the profile must instead have been issued to the authenticated console. This acknowledgement
does not yet implement account-core session teardown or cross-platform offline
propagation.
